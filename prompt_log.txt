PROMPT #6 — Phase 3: Backend Logic & Database Architecture
Date: 2026-09-27
--------------------------------------------------------------------------------
Acting as a senior backend engineer and database architect, design and implement a robust, high-performance backend and persistent data layer for a collaborative Grocery List application (Node.js/Express with an ORM like Prisma or Sequelize, paired with PostgreSQL).

AI Output Summary / Actions Taken:
- Architected enterprise-grade PostgreSQL schema via Prisma ORM (`prisma/schema.prisma`) featuring:
  - Strong relational integrity: Enums (`Role`, `ItemCategory`), cascading foreign keys, and composite unique constraints (`[userId, listId]`).
  - Optimistic Concurrency Control (OCC) through `version Int @default(1)` preventing lost update anomalies during collaborative editing.
  - High-performance composite B-Tree indexes: `@@index([listId, isCompleted])`, `@@index([listId, createdAt(sort: Desc)])`.
- Refactored backend into clean 4-tier layered architecture:
  - `src/config/db.js`: Database lifecycle & PrismaClient connection pooling.
  - `src/repositories/grocery.repository.js`: Data Access Object (DAO) pattern with atomic transactions.
  - `src/services/grocery.service.js`: Domain business logic, input sanitization, and export transformations.
  - `src/controllers/grocery.controller.js`: Strict HTTP REST semantics (200, 201, 400, 404, 409 Conflict, 500).
  - `src/middleware/errorHandler.js`: RFC 7807 compliant standardized error envelopes.
- Solved the "Majority Problem" by eliminating naive full-table scans, unindexed filters, and concurrent state race conditions.
- Validated with 13/13 passing automated unit, integration, and HTTP tests.

PROMPT #7 — Phase 4: Contract Alignment & Shared Source of Truth
Date: 2026-09-27
--------------------------------------------------------------------------------
Acting as a full-stack architect, establish a rigorous API contract and shared source of truth for the collaborative Grocery List application, ensuring the React frontend and Node.js backend perfectly align on structure, naming conventions, and data expectations.

AI Output Summary / Actions Taken:
- Created formal TypeScript contract declarations in `src/contracts/grocery.contract.d.ts` (`GroceryItemContract`, `CreateItemDTO`, `ToggleItemDTO`, `ApiResponse<T>`, `ApiErrorResponse`).
- Created shared contract definition and canonical category dictionary in `src/contracts/grocery.contract.js` (`ItemCategory`, `CategoryDictionary`, `normalizeCategory()`, `getCategoryDisplayLabel()`).
- Built runtime boundary validator in `src/contracts/contractValidator.js` (`validateGroceryItem`, `validateCreateItemDTO`) preventing malformed payloads from penetrating domain logic.
- Identified and fixed critical full-stack mismatches:
  1. Category casing mismatch: Frontend used title-cased strings with spaces ("Meat & Seafood") while PostgreSQL Prisma schema expected screaming snake-case enums (`MEAT_SEAFOOD`). Resolved with bidirectional normalization.
  2. OCC version synchronization: Standardized integer `version` field across client and server mutations to prevent concurrency anomalies.
- Added automated contract alignment test suite in `test_grocery.py` (`test_8_contract_response_alignment`, `test_9_contract_category_normalization`, `test_10_contract_validation_rejections`), bringing suite to 16/16 passing tests.
